iOS & Android platform notes
• Hit targets: every tappable control ≥44×44pt (iOS HIG) / 48×48dp (Material) — our sm button (36px) is icon-only/inline use, never a lone primary CTA.
• Safe areas: screens reserve top inset for the notch/Dynamic Island and status bar (~52px used in these mocks) and bottom inset for the home indicator (~22px extra padding baked into the curved BottomNav).
• Fonts: Sora/Manrope load via web font on both; system fallback stacks (SF Pro on iOS, Roboto on Android) keep text legible before the custom font loads.
• Back navigation: iOS uses the in-header ‹ chevron shown throughout; Android additionally honors the hardware/gesture back button — no extra UI needed, just don't trap navigation in a modal without a close affordance.
• Blur/glass: backdrop-filter blur renders natively on both platforms' modern WebViews; always pair with the semi-opaque glass-fill color as a fallback backdrop.
• Haptics/motion: use the motion tokens (var(--duration-fast), var(--ease-spring)) for press/selection feedback consistently on both platforms.
